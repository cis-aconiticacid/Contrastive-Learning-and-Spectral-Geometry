## 核心发现（post-v3）

### 1. C2（encoder absorption is causal）——**强支持，但需 ε-rescaled 复跑**

v3 最重要的发现：**randdiff 对 predictor Jacobian 的影响在 v2 和 v3 之间方向反转**。

| | v2 联合训练 (n=3) | v3 冻结-encoder (n=2) | randdiff 效果方向 |
|---|---|---|---|
| σ₁: baseline → randdiff | 1.74 → 2.48 | 2.07 → 1.63 | v2: **+43%**；v3: **−21%** ⇒ **反转** |
| SR: baseline → randdiff | 32 → 18 | 20 → 22 | v2: **−43%**；v3: **+10%** ⇒ **反转** |
| F²: baseline → randdiff | 97 → 110 | 87 → 59 | v2: +14%；v3: **−32%** ⇒ **反转** |

**解读**：v2 里 randdiff 的"σ₁ 膨胀 + 谱集中"信号是**联合训练中 encoder 吸收 randdiff 压力的产物**，不是 randdiff 对 predictor Jacobian 的内在效果。冻结 encoder 后，randdiff 表现出 Scarvelis-Solomon 论文的标准 Frobenius 缩水模式。

**未结的反证**：v3 的 ε=0.05 没有针对冻结后 latent norm 重新校准（Confound 3）。可能 ε mis-calibration 也能解释方向反转。需要一个 ε-rescaled frozen_randdiff 复跑（~1.5 GPU-小时）来排除这个解释。在此之前，C2 的强度只能叫"suggestive evidence"，不是"strong evidence"。

### 2. C5 / C7（v2 关于 randdiff 谱信号的 claim）——**需要重写**

- **C5（encoder Jacobian 双向 dichotomy）**：原本说 uvlowr 让 encoder σ₁↓ + SR↑，randdiff 让 encoder σ₁≈ + SR↓。**现在重新解读为 joint training 现象**，不是正则化器本身的性质——因为 v3 里 encoder 完全冻结后，正则化器对 encoder Jacobian 的影响是零（机械必然）。
- **C7（randdiff 把谱集中到 top SV）**：**完全反转**——这是 joint training 的 artifact，不是 randdiff 内在做的事。v3 frozen 里 randdiff 让 F² 缩水 32%，符合 nuclear-norm 直觉。

### 3. C3（uvlowr Pareto improvement）——**弱化**

v2 看上去 uvlowr 在 h≥5 全程领先 baseline。v3 frozen 里：
- h=10: uvlowr (0.20) < baseline (0.27) — uvlowr 领先**但 n=2 方差很大**（seed 0=0.318 输给 baseline；seed 1=0.090 大幅领先）
- h=5: baseline (0.048) < uvlowr (0.10) — uvlowr **输给** baseline
- h=15/20: 方差太大，无法分辨

**结论**：v2 里 uvlowr 的"宽 h≥5 优势"部分来自 encoder co-adaptation（联合训练时 encoder 学会产生"低秩 predictor 友好"的 latent）。冻结 encoder 后这部分优势消失，只剩 architectural prior 提供的窄 h=10 优势——而且这个还要看 seed。

### 4. C1 / C4 / C13 / C6 ——**不变**

- **C1**（Jacobian SR 不预测 rollout）：v3 frozen 三 variant SR ∈ {20.4, 20.8, 22.4}（窄区间），randdiff 是最高 SR 但 rollout 最差——继续违反"SR 越高越好"直觉。
- **C4**（randdiff 伤长程 rollout）：v2 和 v3 都成立。frozen randdiff h=10=0.89 vs baseline 0.27，**3× 差距且 predictor-intrinsic**（不靠 encoder mediated）。
- **C13**（uvlowr r=4 匹配数据 intrinsic dim）：cheap check 独立确认。
- **C6**（trained ViT 都是低 Jacobian SR）：cheap check 独立确认；JEPA vs ImageNet 监督有不同谱特征。

## v3 验证后的关键数字

### Rollout MSE（test, n=256 per horizon）

| variant | h=1 | h=5 | h=10 | h=20 |
|---|---|---|---|---|
| stage1_baseline (joint 20K, n=1) | 0.0068 | 0.082 | 0.081 | 0.220 |
| frozen_baseline (8K, n=2) | 0.0056 ± 0.0001 | 0.048 ± 0.002 | 0.271 ± 0.006 | 1.918 ± 0.482 |
| frozen_uvlowr_r4 (n=2) | 0.008 ± 0.002 | 0.101 ± 0.037 | 0.204 ± 0.161 | 1.993 ± 0.310 |
| frozen_randdiff (n=2) | 0.032 ± 0.002 | 0.224 ± 0.050 | 0.889 ± 0.102 | 2.423 ± 0.243 |

注意：frozen_uvlowr_r4 h=10 两 seed 是 0.318 / 0.090——均值 0.204 被一个 seed 主导，不能下"稳定领先"结论。

### Predictor Jacobian（final step）

| variant | σ₁ | SR | F² |
|---|---|---|---|
| stage1_baseline | 1.715 | 32.36 | 95.16 |
| frozen_baseline | 2.074 ± 0.061 | 20.35 ± 0.80 | 87.95 ± 0.95 |
| frozen_uvlowr_r4 | 2.078 ± 0.037 | 20.81 ± 0.59 | 90.09 ± 6.41 |
| frozen_randdiff | 1.625 ± 0.026 | 22.43 ± 0.38 | 59.12 ± 0.99 |

### 其他 metrics

- **Probe R²（eval, n_test=256）**: 全部 8 个 run = 0.8329（机械必然——encoder 冻结）
- **Encoder Jacobian**: 全部 frozen 变体 σ₁=11.28, SR=2.70, F²=343.7（机械一致，是 freeze 正确性验证）
- **Latent cov SR**: frozen 变体一致 7.95；stage1 8.13
- **uvlowr params**: 6.18M vs baseline 10.79M（**−43%** 确认）
- **训练时间**: frozen 单 run ~670s；stage1 1698s（frozen 比 joint 快 2.5×）

## v3 的 7 个 Confounds（无法在 v3 内排除）

1. **Stage-1 步数 20K（vs v2 的 40K）**：encoder 成熟度不同，v3 和 v2 绝对值对比不公平。
2. **baseline-shaped latents**：stage-1 encoder 只和 full-rank predictor co-train 过。在这个 latent 空间里测 uvlowr/randdiff，不等于"和它们各自 co-train 后再测"。需要 v4。
3. **randdiff ε 没重新校准**：v2 latent norm 和 v3 frozen latent norm 不同，ε=0.05 在 v3 里的"实际正则化强度"未知。**反转可能部分是 ε 错位**——这是 P3 主要 falsifier。
4. **单一 Stage-1 seed**：M2 robustness check 被推迟（"P3 反转了所以不用做"——这是错的逻辑，反转**更需要**鲁棒性确认）。
5. **8K Stage-2 步数可能 undertraining**：pred_loss 没有明显 plateau。
6. **SIGReg 在 Stage-1 开但 Stage-2 关**：Stage-1 encoder 被 SIGReg 塑形了，Stage-2 frozen 训练不再用——非对称。
7. **Stage-2 predictor 从头初始化（8K）vs v2 co-trained predictor（40K）**：v2-v3 绝对 σ₁ 对比里这部分差异不能归因到 freeze。

## 下一步建议（优先级排序）

1. **ε-rescaled frozen_randdiff 复跑**（~1.5 GPU-小时）：先在冻结 latent 上测 |z| 平均范数，按比例调 ε。如果反转持续 → C2 strong evidence；如果回到 v2-like 膨胀 → 反转是 ε 错位。**强力推荐先做这个**。
2. **v4 实验**：uvlowr-co-trained Stage-1 + freeze + 多 predictor 测试。直接解决 Confound 2。~8 GPU-小时。
3. **Stage-1 seed sweep**：第二个 Stage-1 跑 randdiff 看 P3 反转是否稳健。
4. **Hyperparam sweep**：uvlowr rank ∈ {2, 4, 8, 16, 32} + randdiff λ ∈ {0.001, 0.01, 0.1}。closes C1。
5. **Push-T planning success rate eval pipeline**（~1 天工程）：补 v2/v3 缺的 task-level metric。

## 关键工程教训（写进 memory，避免重蹈）

详见 `/root/.claude/projects/-workspace/memory/project_lewm_lowrank.md`：
- AutoDL 默认 60GB 系统盘不够（Push-T h5 解压 27GB+）；要 expand 80GB。
- west-D 区某些 host 网络极差（<1MB/s pip）；速度测试 <1MB/s 直接弃用重开。
- tsinghua/aliyun pip mirror via 全局 `~/.pip/pip.conf` 必须。
- 多个并发 setup 进程会 clobber `setup.log`；用 `flock -n` 互斥。
- `pkill -f "pip install"` 会把执行它的 bash -c 自己也匹配掉——必须用具体 PID 或写独立清理脚本。
- SSH paramiko exec_command 默认从 `/root` 跑，repo 操作必须前缀 `cd /workspace/le-wm &&`。
- 磁盘紧张时用 `os.unlink(file)` while fd open 流式解压可省一份输入文件空间。
- Lightning 模块 freeze 不要用 `module.train = MethodType(...)`——会破坏 `torch.save(model)`。用 callback (`KeepFrozenInEvalCallback`) 每 batch 重置 eval 模式。
- AutoDL 计费 ¥3/hr；跑完立刻 release。
